# Inference on MCXN236

Run the [OnePolicy](https://github.com/Xygarde69/OnePolicy) quadruped locomotion
policy on an **NXP FRDM-MCXN236** board (Arm Cortex-M33 @ 150 MHz, 1 MB flash),
and steer the simulated robot by **tilting the board**.

```
          PC (MuJoCo, OnePolicy's play.py)                      FRDM-MCXN236
 ┌────────────────────────────────────────────┐   USB-C (J10)  ┌──────────────────────────────┐
 │ simulate ANYmal C ─► 51 observations ──────┼──────────────► │ FXLS8974CF tilt ─► command   │
 │                                            │  921600 baud   │ normalize ─► MLP 51-512-256- │
 │ apply 12 joint actions ◄── actions+command ┼◄────────────── │ 128-12 (ELU), weights in     │
 │ command enters the next observation        │   every 20 ms  │ flash, 11.3 ms per inference │
 └────────────────────────────────────────────┘                └──────────────────────────────┘
```

The PC only simulates. Every 50 Hz control step it sends the robot's
observations to the board; the board runs the policy and sends back the joint
actions plus the velocity command read from its accelerometer. OnePolicy is used
unmodified: `host/play_nxp.py` imports its `play.py` and redirects the policy
and the command to the board at run time.

Measured on hardware: the board's actions match PyTorch to < 1e-6, one inference
takes 11.3 ms, and the full round trip (including the accelerometer read) is
15.2 ms, inside the 20 ms control period.

## Contents

| Path | What |
|---|---|
| `policy/` | The firmware: serial protocol (`main.c`), MLP (`policy_net.c`), tilt command (`tilt.c`), settings (`Kconfig`) |
| `policy/model/` | The policy weights as C arrays, generated by `host/nxp_policy.py export` (OnePolicy's `OnePolicy.pt` is checked in) |
| `host/nxp_policy.py` | PC side: `export` the model, `tilt` (live tilt check), `bench` (accuracy + timing), the serial link |
| `host/play_nxp.py` | Runs OnePolicy's `play.py` with the policy and the command on the board |
| `accel/` | Accelerometer readout demo (prints X/Y/Z in mg) |
| `docs/` | MCU datasheet and board user manual |
| `manifest/west.yml` | Pulls only the MCUXpresso SDK v26.09.00 parts this board needs |

## Run it from scratch

Tested on Arch Linux. You need an NVIDIA GPU for the simulation, git,
[uv](https://docs.astral.sh/uv/), and the board connected by its **MCU-Link
USB-C port (J10)**. That one cable does flashing and the serial link.

### 1. Clone both projects next to each other

```bash
mkdir -p ~/Documents/Projects && cd ~/Documents/Projects
git clone https://github.com/Xygarde69/OnePolicy.git
git clone git@github.com:Xygarde69/Inference_on_MCX236.git Inference
```

The host scripts look for OnePolicy at `../OnePolicy`. If it is somewhere else,
`export ONEPOLICY_DIR=/path/to/OnePolicy`.

### 2. Set up OnePolicy (simulation)

```bash
cd ~/Documents/Projects/OnePolicy
uv venv .venv --python 3.11
uv pip install --python .venv/bin/python -r requirements.txt
```

The host scripts in this repo run with OnePolicy's interpreter (it has torch and
mjlab). They need nothing extra: the serial link uses the standard library.

```bash
export PY=~/Documents/Projects/OnePolicy/.venv/bin/python
```

### 3. Set up the firmware toolchain

```bash
sudo pacman -S --needed arm-none-eabi-gcc arm-none-eabi-newlib arm-none-eabi-gdb cmake ninja
cd ~/Documents/Projects/Inference
uv sync                                    # west, pyocd, SDK build-script deps
uv run west update --narrow -o=--depth=1   # fetch the SDK (~2 GB) into mcuxsdk/
uv run pyocd pack install MCXN236VDF       # flash algorithm for pyOCD
uv run pyocd list                          # should show "MCU-LINK FRDM-MCXN236"
```

If opening the serial port later fails with "Permission denied", add yourself
to the group that owns it (`ls -l /dev/ttyACM*`; `uucp` on Arch, `dialout` on
Debian/Ubuntu): `sudo usermod -aG uucp $USER`, then log in again.

### 4. Build and flash the firmware

Run every `uv run west` / `uv run pyocd` command from inside `Inference/`. Outside
it, uv can't find west ("Failed to spawn: west").

```bash
cd ~/Documents/Projects/Inference
source env.sh                              # ARMGCC_DIR=/usr
uv run west build -p always policy -b frdmmcxn236 -d build_policy --config release
uv run pyocd flash build_policy/policy.elf
```

The repo already contains OnePolicy's weights (`policy/model/`). To put a
different checkpoint on the board, export it first and rebuild:

```bash
$PY host/nxp_policy.py export /path/to/model_XXXX.pt
```

### 5. Check the board

```bash
$PY host/nxp_policy.py bench    # max |board - float64| ~7e-7, inference ~11.3 ms
$PY host/nxp_policy.py tilt     # hold it still (that's "stand still"), then tilt: forward / left in m/s
```

Tilt the board's edges and check that `forward` and `left` change the way you
want. If one is reversed or they are swapped, see [Tilt settings](#tilt-settings).

### 6. Walk ANYmal C

Hold the board in the pose you want to mean "stand still" while it starts:

```bash
$PY host/play_nxp.py --robot anymal_c_xknee
```

A MuJoCo viewer opens (or a viser page at http://localhost:8080 without a
display). Tilt forward/back to walk forward/back and left/right to walk
sideways. Every 250 steps it prints the board's inference time, the round trip,
the difference from the PyTorch policy and the current tilt command.

Any other `play.py` option passes through. Turning comes from play.py, since the
tilt only sets the linear direction:

```bash
$PY host/play_nxp.py --robot anymal_c_xknee --command "(0, 0, 0.3)"   # turn at 0.3 rad/s
$PY host/play_nxp.py --robot anymal_c_xknee --joystick True           # DualSense L1/R1 turn
$PY host/play_nxp.py --robot spot                                     # another robot
$PY host/play_nxp.py --robot go2 --command-source pc --command "(0.5, 0, 0)"   # ignore the tilt
```

`$PY host/play_nxp.py --help` lists both this script's and play.py's options:

| Option | Default | |
|---|---|---|
| `--port` | the MCU-Link VCOM, found by `/dev/serial/by-id` | Board serial port |
| `--baud` | 921600 | Must match `BOARD_DEBUG_UART_BAUDRATE` |
| `--command-source` | `tilt` | `pc`: forward/sideways from play.py instead of the tilt |
| `--no-zero` | off | Keep the board's previous neutral pose |
| `--policy` | `OnePolicy/OnePolicy.pt` | Must be the checkpoint flashed on the board (checked by CRC) |

## Tilt settings

Set in `policy/Kconfig` (rebuild and reflash after changing):

| Setting | Default | |
|---|---|---|
| `TILT_FORWARD_AXIS` | 0 | Accelerometer axis pointing forward: 0 = X, 1 = Y (the other is left) |
| `TILT_FORWARD_SIGN` / `TILT_LEFT_SIGN` | 1 | Set -1 to reverse a direction |
| `TILT_DEADZONE_DEG` | 5 | Tilt below this does nothing |
| `TILT_FULL_DEG` | 25 | Tilt for full speed |
| `TILT_MAX_FORWARD_MMS` / `_BACKWARD_` / `_LATERAL_` | 1000 / 500 / 500 | Full-tilt speeds in Go2 mm/s (scaled to the robot) |
| `TILT_SMOOTHING_PCT` | 20 | Low-pass: % of the way to the new command each 20 ms step |

The tilt is measured from the gravity direction relative to the pose at
startup, so the board doesn't have to lie flat.

## Serial protocol

Little-endian frames. Every frame ends with the XOR of its command and payload bytes.

| Request (`0xA5 cmd payload xor`) | Reply (`0x5A cmd payload xor`) |
|---|---|
| `I` | u32 model CRC32, u16 n_obs, u16 n_act, u32 core Hz, u8 accelerometer ok |
| `P` + 51 × f32 observations | 12 × f32 actions, f32 forward, f32 left (Go2 m/s), u32 inference cycles |
| `C` | f32 forward, f32 left (tilt command, no inference) |
| `Z` | u8 ok: the current pose becomes "stand still" |
| (bad frame) | `E` + u8 code: 1 checksum, 2 unknown command, 3 UART error |

## Troubleshooting

- **`Failed to spawn: west`**: run it from inside `Inference/`.
- **`No reply from the board`**: the policy firmware isn't flashed, or a terminal
  (miniterm, screen) has the port open. Close it.
- **`Board model CRC ... != checkpoint`**: the board holds a different policy than
  `--policy`. Export that checkpoint, rebuild and reflash.
- **`/dev/ttyACM0` missing**: the board can re-enumerate as `ttyACM1` after
  flashing. The scripts find it by its `/dev/serial/by-id` name automatically.
- **The robot walks the wrong way when tilted**: flip `TILT_*_SIGN` or `TILT_FORWARD_AXIS`.

## Limits

- Only the flat-ground policy fits. The weights are float32 in flash (752 kB of
  1 MB). The rough-terrain `OnePolicy_r` (~1.1 MB) would need fp16/int8 weights.
- Running play.py still writes play.py's usual files inside OnePolicy: the
  robot's `*.temp.xml` and Python's `__pycache__`, both git-ignored there.
  No OnePolicy file is edited.

Board and SDK details for development are in [CLAUDE.md](CLAUDE.md).
